# AnyKeyMic 原生 USB 麦克风桥接

## 状态

已实现并通过 Windows x64 实机验收。

## 背景

原 AnyKey AI 基于 Electron，启用桥接时需要把键盘麦克风音频输出到 VB-CABLE 的 `CABLE Input`，再由系统和其他应用从 `CABLE Output` 读取。原实现存在默认设备别名和桥接设备状态不同步的问题，也不能满足启动后自动开麦和断线后自动恢复的需求。

本变更新增一个无界面的原生后台程序 `AnyKeyMic`，保留 VB-CABLE 作为第一版音频出口。

## 目标

- Windows x64 登录后可后台运行。
- 连接 USB 键盘后自动完成握手并发送开麦命令。
- 键盘拔出、重新插入后自动重新枚举、握手并恢复开麦。
- 音频始终输出到用户明确选择的实体虚拟声卡端点。
- 虚拟声卡不可用时等待恢复，不回退到物理扬声器。
- 不保存录音，只记录连接状态和简要音量统计。
- 为后续 macOS Apple Silicon、BlackHole 和自有虚拟音频驱动保留可替换接口。

## 非目标

- 第一版不支持蓝牙或 2.4G 私有音频编码 `0x1B`。
- 第一版不实现 Windows 或 macOS 自有虚拟音频驱动。
- 第一版不提供图形界面。
- 第一版不作为 Windows 系统服务运行，使用当前用户登录启动。

## 技术方案

### 共享核心

Swift 实现协议状态机、握手、自动开麦、心跳、音频存活判断和重连状态。状态机收到设备停止通知后会重新发送开麦命令，避免常开状态因固件事件丢失。

### Windows 原生适配

C 适配层使用 HIDAPI 非独占打开厂商 HID 接口，识别 VID `0x248A`、PID `0x8102`、厂商 Usage Page `>= 0xFF00`。音频使用 miniaudio 的 WASAPI 后端，并绑定保存的实体端点 ID。

USB 音频报文为 report ID `0x1C`，从偏移 4 读取 30 个小端 `Int16` 样本，采样率为 16 kHz、单声道。音频回调使用预分配环形缓冲区，欠载补零，满载丢弃新帧。

### 自动启动

Windows 使用当前用户 Startup 启动项；macOS 预留 LaunchAgent 脚本。程序使用单实例锁，避免多个桥接程序同时向同一键盘发送命令。

## 使用方式

```powershell
anykey-mic devices
anykey-mic configure 3
anykey-mic run
```

`3` 仅代表本机验收时的设备序号，使用前应以 `devices` 输出为准。系统输入继续选择 `CABLE Output`，系统物理输出继续选择扬声器或耳机。

## 风险与限制

- 蓝牙音频使用官方私有编码，原项目只有厂商预编译 Node 模块，没有可直接复用的解码源码；当前程序遇到 `0x1B` 会明确报不支持，不会静默输出噪声。
- 目前 macOS 适配代码尚未在 Apple Silicon 实机验证。
- 睡眠期间不收音，唤醒后依赖设备重新枚举和会话恢复。
- 长期后台运行前仍需增加日志轮转和更完整的睡眠唤醒测试。
